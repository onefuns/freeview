# 버전 현황

프로젝트의 공식 산출물은 개발명세 2개와 대응 프리뷰 2개다.

| 산출물 | 파일 | 현재 버전 | 기준일 | 상태 |
|---|---|---|---|---|
| 관리자 개발명세 | `ADMIN_SPEC.md` | `v4.7.0-draft` | 2026-11-12 | 검토 중 |
| 관리자 HTML 프리뷰 | `legacy-admin-preview/index.html` | `v4.7.0-preview.1` | 2026-11-12 | 검토용 |
| 쇼핑몰 프론트 개발명세 | `STOREFRONT_SPEC.md` | `v4.9.0-draft` | 2026-11-12 | 검토 중 |
| 쇼핑몰 HTML 프리뷰 | `html-preview/index.html` | `v4.8.0-preview.1` | 2026-11-11 | 검토용 |

## 버전 규칙

- 개발명세는 `MAJOR.MINOR.PATCH-draft` 형식을 사용한다.
- 프리뷰는 개발명세의 기준 버전에 `-preview.N`을 붙인다.
- 구조·업무 흐름의 호환 불가능한 변경은 `MAJOR`를 올린다.
- 기능이나 화면 추가·변경은 `MINOR`를 올린다.
- 문구, 목업 데이터, 오탈자처럼 의미가 바뀌지 않는 변경은 `PATCH`를 올린다.
- 같은 개발명세에서 프리뷰만 수정할 때는 `preview.N`만 올린다.

## 변경 절차

1. 관리자 또는 쇼핑몰 개발명세를 수정한다.
2. 화면 변경이 있으면 대응하는 HTML 프리뷰를 수정한다.
3. `CHANGELOG.md`에 정책·기능·화면 영향을 한 번만 기록한다.
4. 네 산출물의 버전을 이 문서와 각 파일 헤더에 동기화한다.
5. 문법 검사와 브라우저 동작 검수를 통과한 버전만 Git 커밋으로 남긴다.
