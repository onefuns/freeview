# 에그라우터 Telegram Mini App 쇼핑몰 개발명세

| 항목 | 내용 |
|---|---|
| 문서 ID | EGGROUTER-STOREFRONT-SPEC |
| 버전 | v4.9.0-draft |
| 기준일 | 2026-11-12 |
| 적용 대상 | 판매점·영업점 관리자, Telegram Mini App 쇼핑몰 |

> 통합 관리자의 조직·주문·재고·개통·충전·정산 기준은 `ADMIN_SPEC.md`를 적용한다. 이 문서는 고객 화면과 판매점·영업점이 관리하는 쇼핑몰 콘텐츠 및 관리자 연동 계약만 정의한다.

## 1. 기본 원칙

1. 기존 관리자 화면과 수동 업무 방식을 최대한 유지한다.
2. 쇼핑몰은 고객 주문을 받는 독립 판매 채널이다.
3. 쇼핑몰 상품은 기존 코드관리의 모델·요금제·재고 상품과 매칭하지 않는다.
4. 일반 쇼핑몰 상품 주문·결제는 실제 신규주문·재고·장비·요금제와 연결하지 않는다.
5. 판매점·영업점은 기존 방식으로 자유입력 신규주문을 작성한 뒤 자기 직접 고객계정을 수동 매칭한다.
6. 대리점이 매칭된 신규주문에 실제 재고를 할당하면 해당 고객 장비가 자동 생성된다.
7. 고객이 나의 장비에서 기존 요금제와 연장 개월을 선택해 결제하면 충전요청을 자동 생성한다.
8. 자동화 대상은 충전요청 접수까지이며 실제 충전처리는 대리점이 기존 방식으로 수행한다.
9. 관리자 개인계정을 Bot에 직접 연결하지 않고 관리자→소속 조직→쇼핑몰 테넌트→Bot·도메인 순서로 연결한다.
10. 쇼핑몰 미사용 조직은 기존 관리자 수동기능만 사용하며 쇼핑몰 데이터와 Bot 연결을 생성하지 않는다.

## 3. 메뉴와 화면

### UI-STORE-SET-001 미니앱 설정

- 관리자 계정은 `organization_members`를 통해 판매점 또는 영업점 조직에 소속된다.
- 쇼핑몰을 사용하는 조직에만 `storefront_tenant_id`를 발급한다.
- 입력·표시: 미니앱 사용 여부, 연결 조직, 쇼핑몰명, 로고, 대표색상, Bot username, 암호화 Bot Token, Mini App 도메인, 운영상태, 마지막 검증일시
- Bot Token 원문은 등록·교체 입력 시에만 받고 저장 후 다시 표시하지 않는다.
- 조직에 권한 있는 관리자 여러 명이 같은 쇼핑몰을 운영할 수 있다.
- 대리점은 개설승인·연결상태·오류만 관리하고 판매점·영업점의 고객·리뷰 원문은 조회하지 않는다.
- 상태: `미개설 → 개설신청 → 설정중 → 검증대기 → 사용중`, 예외 상태는 `설정오류`, `사용중지`다.

### UI-STORE-CAT-001 상품 분류

- 입력: 분류명, 설명, 노출상태, 노출순서
- 기능: 등록, 수정, 노출·숨김, 위·아래 순서 이동
- 운영 상품 분류코드와 연결하지 않는다.

### UI-STORE-PROD-001 상품 판매 등록

- 입력: 분류, 상품명, 고객 판매가, 대표 이미지, 상품 요약, 상품 상세정보, 노출상태, 노출순서
- 상품 상세정보는 단순 textarea가 아니라 네이버 스마트에디터와 동급 사용성을 갖춘 WYSIWYG 에디터를 필수로 사용한다. 특정 제품 종속을 의미하지 않으며 동일 수준의 상용·오픈소스 에디터를 선택할 수 있다.
- 필수 편집기능: 제목·본문, 굵게·기울임·밑줄·취소선, 글자색, 목록, 좌·중앙·우 정렬, 링크 등록·수정·해제, 실행취소·재실행, 서식 제거
- 본문 이미지 기능: 다중 업로드, 업로드 진행·실패 표시, 본문 위치 삽입, 대체문구, 표시크기, 정렬, 삭제
- 링크 기능: 표시문구, URL, 새 창 여부를 편집하며 `http`, `https` 등 허용된 URL 스킴만 저장한다.
- 등록과 수정은 동일한 에디터 컴포넌트·저장형식을 사용하며 저장 후 재진입했을 때 내용·이미지·링크가 동일하게 복원되어야 한다.
- 운영 이미지 파일은 별도 파일 스토리지에 저장하고 에디터 본문에는 관리 URL만 참조한다. Base64 이미지 본문 저장은 허용하지 않는다.
- 서버는 저장 시 허용목록 기반 HTML 정제를 수행해 script, iframe, 이벤트 속성과 위험 URL을 제거한다. 미니앱 출력 시에도 정제된 콘텐츠만 렌더링한다.
- 판매점·영업점이 모든 표시정보를 직접 작성한다.
- 기존 Model, 요금제, 재고코드 선택 필드는 제공하지 않는다.
- 노출상태 후보: 노출, 숨김, 품절

### UI-STORE-SORT-001 노출 순서 관리

- 상품 분류 노출순서 변경
- 분류 안의 상품 노출순서 변경
- 위·아래 이동 또는 순번 입력을 지원한다.
- 변경 후 쇼핑몰 표시순서에 반영한다.

### UI-STORE-PAGE-001 콘텐츠 페이지 관리

- 판매점·영업점은 자기 쇼핑몰에서 안내, 이용방법, 프로모션 등 배너가 연결될 콘텐츠 페이지를 생성·수정한다.
- 입력: 페이지 제목, URL 경로(slug), 요약, 본문, 공개상태, 공개 시작·종료일시
- 공개상태는 `초안`, `공개`, `숨김`으로 관리하며 초안·숨김 페이지는 고객 화면에 직접 노출하지 않는다.
- URL 경로는 쇼핑몰 테넌트 안에서 유일해야 하며 페이지 ID는 제목이나 경로가 변경되어도 유지한다.
- 본문은 `UI-STORE-PROD-001`과 같은 스마트 에디터급 WYSIWYG 컴포넌트·저장·보안정책을 사용한다. 이미지, 링크, 제목, 본문서식, 목록과 정렬을 지원한다.
- 관리자는 저장 전 미리보기와 공개 후 실제 고객 URL 열기를 사용할 수 있다.
- 공개 중인 배너가 연결된 페이지는 즉시 삭제할 수 없다. 먼저 배너 연결을 해제하거나 페이지를 숨김 처리하며 변경이력을 감사로그에 남긴다.

### UI-STORE-BANNER-001 배너 관리

- 판매점·영업점 자기 쇼핑몰에만 제공한다.
- 배너 위치: 상단, 중단, 하단
- 입력: 배너명, 이미지, 대체 텍스트, 위치, 노출상태, 시작·종료일시, 노출순서, 클릭 연결 유형과 대상
- 클릭 연결 유형: 연결 없음, 쇼핑몰 상품, 상품 분류, 쇼핑몰 콘텐츠 페이지, 외부 URL
- 콘텐츠 페이지 연결 시 현재 조직에서 `공개` 상태인 페이지만 선택할 수 있고 고객은 해당 쇼핑몰 내부 페이지로 이동한다.
- 같은 위치의 활성 배너는 노출순서 오름차순으로 표시한다.
- 노출기간 전에는 예약, 기간 중에는 노출중, 종료 후에는 종료로 계산한다. 관리자가 숨김 처리하면 기간과 관계없이 표시하지 않는다.
- 배너 변경·숨김·순서변경은 감사로그에 기록한다.

### UI-STORE-REVIEW-001 리뷰 관리

- 고객 입력: 별점 1~5점과 최대 100자의 한 줄 리뷰
- 작성 조건: 결제완료된 일반 쇼핑몰 주문상품이며 고객·주문·상품·쇼핑몰 테넌트가 모두 일치해야 한다.
- 주문상품 하나당 고객 리뷰 1개만 작성한다. 고객은 자기 리뷰를 수정·삭제할 수 있으며 변경이력을 보존한다.
- 목록: 작성일, 주문번호, 고객계정, 상품, 별점, 한 줄 리뷰, 노출상태
- 검색: 평점, 노출상태, 상품, 주문번호, 고객번호, 리뷰 내용
- 판매점·영업점은 자기 쇼핑몰 리뷰만 조회하고 노출·숨김을 처리한다.
- 관리자는 고객이 작성한 별점과 리뷰 원문을 수정할 수 없다.
- 숨김·복구에는 처리 사유가 필수이며 처리자·처리일시·이전상태를 감사로그에 기록한다.
- 상품목록·상세에는 노출중 리뷰만 사용해 평균별점과 리뷰수를 계산한다.

### UI-STORE-ORDER-001 고객 주문관리

- 검색: 주문구분, 결제상태, 운영연계, 주문일 범위, 주문번호, 고객번호, 로그인 아이디, 상품명, CTN
- 일반상품 주문 목록: 주문번호, 주문일, 고객계정, 노출상품, 결제금액, 결제상태, 운영연계 없음
- 연장 주문 목록: 주문번호, 고객계정, 고객 장비·CTN, 기존 요금제, 연장 개월, 결제금액, 결제상태, 생성된 충전요청
- 일반상품 주문은 실제 신규주문·장비와 연결하지 않는다.
- 연장 주문은 결제완료 시 동일 장비·현재 요금제·선택 개월로 충전요청을 한 번만 자동 생성한다.
- 판매점과 영업점은 자기 직접 고객 주문만 조회한다.

### UI-CUST-ASSET-001 고객 장비관리

- 판매점·영업점에만 제공하고 대리점에는 제공하지 않는다.
- 검색: 매칭상태, 장비상태, 고객번호, 로그인 아이디, Telegram, 신규주문번호, CTN, Serial, 매칭일
- 목록: 고객계정, 판매귀속, 신규주문, CTN·USIM, Model·Serial, 현재 요금제, 만료일, 처리상태, 나의 장비 노출상태
- 고객계정과 신규주문 매칭은 판매점·영업점 담당자가 수행한다.
- 대리점의 실제 재고 할당을 기준으로 장비·회선·구독을 자동 생성한다.
- 잘못된 매칭의 변경·해제와 장비 교체는 사유와 감사로그를 남긴다.

### UI-CUST-AUTH-001 고객계정

- 가입: Telegram initData 서버 검증 후 로그인 아이디·비밀번호 생성
- 회원정보에는 이름·휴대폰·이메일을 필수 수집하지 않는다.
- 주문 수령인 이름·연락처·주소는 고객계정이 아니라 주문별 정보로 보관한다.
- 평상시에는 연결된 Telegram user ID로 자동 로그인한다.
- 새 Telegram 계정에서는 `기존 계정 연동`을 선택하고 로그인 아이디·비밀번호가 일치하면 동일 customer_id에 연결한다.
- 연결 완료 후 기존 Telegram identity는 비활성화하고 새 identity를 활성화한다.
- 비밀번호 원문은 저장·표시하지 않고 해시만 저장한다.

## 4. 신규 주문 폼

기존 관리자 방식과 동일하게 다음 두 필드만 사용한다.

- 주문 요청일
- 주문 내용 자유입력

주문 내용에는 통신사, 모델, 요금제, 수량, 수령인 이름·연락처, 배송 요청사항 등 담당자가 필요한 정보를 자유롭게 작성한다. 선택박스로 주문 구성을 강제하지 않는다.

## 5. 데이터 분리와 연결

```text
쇼핑몰 영역
storefront_categories
storefront_products
storefront_banners
storefront_customer_orders
storefront_reviews
        │ 일반상품 주문은 운영영역과 미연결
        │ 나의 장비 연장 주문만 recharge_requests 자동 생성
        ▼
기존 운영 영역
orders / inventory / procurements / recharge_requests
```

- 두 영역 사이에 상품코드 외래키를 두지 않는다.
- 고객 주문 당시 상품명, 설명 요약, 가격, 수량을 스냅샷으로 보존한다.
- 신규주문은 쇼핑몰 주문과 연결하지 않고 판매점·영업점이 기존 방식으로 별도 작성한다.
- 신규주문에는 선택적으로 `customer_id`를 매칭하며 같은 판매귀속의 직접 고객만 검색할 수 있다.
- 매칭된 신규주문에 재고가 할당되면 `customer_assets`와 `subscriptions`를 자동 생성한다.
- 배송완료·개통완료 후 고객 장비를 미니앱에 노출한다.
- 연장 주문에는 `customer_asset_id`, `subscription_id`, 기존 요금제, 연장 개월, 생성된 `recharge_request_id`를 저장한다.
- `storefronts`는 `organization_id`와 1:1 활성 연결을 기본으로 하고 Bot 교체 이력은 1:N으로 보존한다.
- 배너와 리뷰는 반드시 `tenant_id`, `storefront_id`를 가지며 조직 범위 검증 없이 직접 조회하지 않는다.
- 리뷰는 `storefront_order_item_id`에 고유 제약을 두어 주문상품당 한 건만 허용한다.
- 리뷰 원문·별점 변경과 관리자 노출상태 변경은 별도 이력 테이블에 보존한다.

## 6. 자동화 범위

### 자동화 제외

- 쇼핑몰 일반상품과 운영 상품 자동 매칭
- 일반상품 결제에 따른 신규주문 자동 생성
- 일반상품 결제에 따른 운영 재고 예약·차감
- 발주 요청·개통 요청 자동 생성
- 실제 통신사 충전 처리

### 자동화 포함

- 고객계정과 매칭된 신규주문에 대리점 재고 할당 시 고객 장비 자동 생성
- 배송·개통완료 시 나의 장비 자동 노출
- 나의 장비 연장 결제완료 시 충전요청 자동 생성
- 충전완료 시 동일 고객 장비의 만료일 갱신
- 결제 주문 한 건당 충전요청 한 건을 보장하는 멱등성 처리
- 배너 시작·종료일시에 따른 노출상태 계산
- 노출중 리뷰 기준 상품별 평균별점·리뷰수 집계

## 7. 프론트 디자인·템플릿 기준

### UI-STORE-THEME-001 선택형 템플릿

- 모든 판매점·영업점 쇼핑몰은 동일한 프론트 코드와 컴포넌트를 사용한다.
- 설계·검토 단계에서는 `가이드 매거진형`, `상품 카탈로그형`, `프로모션 캠페인형` 3개 레이아웃을 후보로 유지하고 DEV 프리뷰에서 비교한다.
- 실제 프론트 개발 착수 전 프로젝트 공통 기준 레이아웃 하나를 최종 선정한다. 운영 환경에서 판매점·영업점이 레이아웃을 개별 선택하는 기능은 제공하지 않는다.
- 세 후보는 동일 데이터·공통 컴포넌트를 사용하며 선정된 레이아웃 안에서 로고, 쇼핑몰명, 브랜드 컬러, 컬러셋, 라이트·다크 테마, 배너와 콘텐츠를 조직별로 설정한다.
- 개발 착수 후 공통 레이아웃 변경은 관리자 설정이 아니라 별도 디자인 버전 변경으로 관리한다.
- 사용자 정의 JavaScript·CSS·임의 HTML 레이아웃은 허용하지 않는다.
- 설정은 초안과 공개본을 분리하고 Telegram 실제 화면 미리보기 후 공개한다.

### UI-STORE-HOME-001 설명·홍보 중심 메인

- 라우터·eSIM을 모르는 고객을 기준으로 전문용어보다 사용 목적과 이용 방법을 먼저 설명한다.
- 메인은 `라우터 설명 → 사용 목적 선택 → 이용 3단계 → 추천 상품 → 판매자 배너 → 상품 유형 → 리뷰 → 상담` 흐름을 기본으로 한다.
- 상품 카드에는 추천 대상, 데이터 구성, 동시 연결 수, 장비 포함 여부, 가격, 별점과 리뷰 수를 우선 표시한다.
- CTN, Serial, USIM 식별정보 등 운영용 정보는 상품 홍보 화면에 노출하지 않는다.

### UI-STORE-HERO-001 메인 롤링 배너

- 상단 메인 배너는 최소 2개, 최대 5개를 등록할 수 있다.
- 배너는 이미지 또는 시스템 제공 비주얼, 제목, 설명, 버튼문구, 연결대상, 노출기간, 노출순서를 가진다.
- 자동 전환 기본 간격은 5초이며 사용자가 페이지 인디케이터로 직접 전환할 수 있다.
- 사용자가 배너를 조작하면 자동 전환 시간을 다시 시작한다.
- 접근성 설정에서 동작 줄이기를 사용하는 경우 자동 전환을 중지한다.
- 판매자 배너는 실제 상품·공지·상담·외부 허용 URL에 연결할 수 있다.

### UI-STORE-COLOR-001 컬러·밝기 테마

- 판매자는 브랜드 컬러 또는 시스템 컬러셋을 선택한다.
- 시스템 컬러셋 기본 후보는 오션 블루, 포레스트 민트, 선셋 코랄이다.
- 라이트·다크 테마를 지원하며 모든 조합에서 텍스트·버튼 대비와 상태색을 검수한다.
- 결제, 오류, 성공, 취소와 경고 상태색은 브랜드 컬러에 의해 의미가 바뀌지 않게 공통 토큰으로 고정한다.

### UI-STORE-REVIEW-DISPLAY-001 리뷰·평점 노출

- 리뷰·평점은 선택 가능한 3개 후보 레이아웃과 최종 선정 레이아웃 모두에 반드시 포함하는 공통 필수기능이다.
- 상품 카드에는 평균별점과 리뷰 수, 상품 상세에는 평점 요약·리뷰 목록·전체 리뷰 이동을 표시한다.
- 메인과 전체 리뷰 화면에는 평균평점, 별점 1~5점 분포, 전체 리뷰 수를 함께 표시한다.
- 전체·쉬운 사용·빠른 연결·배송 만족 등 키워드 칩으로 고객이 리뷰 성격을 빠르게 파악할 수 있게 한다.
- 리뷰 카드는 별점, 구매인증 배지, 최대 100자의 한 줄 리뷰, 구매 옵션, 마스킹 계정, 작성일을 간결하게 표시한다.
- 고객 반응은 `도움돼요` 한 가지로 제한해 소셜 커머스의 신뢰 신호는 유지하면서 화면 복잡도를 낮춘다.
- 구매인증은 결제완료 주문상품과 리뷰 작성 고객이 일치할 때만 서버에서 부여하며 판매자가 임의로 지정할 수 없다.

### UI-STORE-IMAGE-001 실사형 상품 이미지

- 메인 배너, 상품목록, 추천상품, 캠페인 픽과 상품상세는 CSS 도형 대신 실제 상품 사진 또는 판매 권한이 확보된 실사형 이미지를 사용한다.
- 실제 제품 사진을 확보하지 못한 프리뷰에서는 공개된 외형·크기·포트 구성을 참고해 제작한 이미지를 사용할 수 있으나 `프리뷰용 이미지`임을 명시한다.
- 상품목록과 상세 이미지는 같은 상품 에셋을 사용하며 배경, 비율과 크롭 규칙을 템플릿 간 동일하게 유지한다.
- eSIM 요금제는 물리 SIM 도형 대신 스마트폰 개통 장면 등 디지털 상품의 사용 맥락이 드러나는 이미지를 사용한다.
- 운영 배포 전 판매자가 권리를 보유한 정식 상품 이미지로 교체하고 이미지 출처·사용 권한을 관리한다.

## 8. 검수 기준

1. 미니앱 사용 판매점과 영업점에 미니앱 설정·상품관리·콘텐츠 페이지관리·배너관리·리뷰관리·고객주문관리·고객 장비관리 메뉴가 표시된다.
2. 대리점에는 판매자용 상품 등록 메뉴가 표시되지 않는다.
3. 상품 등록 시 기존 상품코드·모델·요금제·재고 선택이 요구되지 않는다.
4. 분류와 상품의 노출순서를 변경할 수 있다.
5. 고객 주문을 자기 쇼핑몰 범위에서만 조회할 수 있다.
6. 일반상품 주문은 신규주문·운영 상품·재고와 연결되지 않는다.
7. 판매점·영업점 신규주문에서 자기 고객계정만 수동 매칭할 수 있다.
8. 매칭 신규주문에 대리점 재고 할당 시 실제 장비가 고객에게 자동 귀속된다.
9. 대리점 화면에는 고객 로그인 아이디·Telegram ID가 표시되지 않는다.
10. 영업점 주문은 판매점 승인 후에만 대리점 신규주문 요청에 표시된다.
11. 나의 장비 연장 결제완료 시 고객주문 내역과 충전요청이 각각 한 건 생성된다.
12. 관리자 개인계정이 변경되어도 조직에 연결된 쇼핑몰 테넌트·Bot·상품·고객 데이터는 유지된다.
13. 미니앱 미사용 조직은 기존 수동 관리자 기능을 그대로 사용하며 쇼핑몰 메뉴와 데이터가 활성화되지 않는다.
14. 판매점과 영업점은 상단·중단·하단 배너를 등록하고 위치별 순서·기간·클릭대상을 관리할 수 있다.
15. 결제완료 주문상품의 고객만 별점 1~5와 최대 100자의 한 줄 리뷰를 한 건 작성할 수 있다.
16. 판매점·영업점 관리자는 자기 쇼핑몰 리뷰의 노출상태만 변경할 수 있고 별점·원문을 수정할 수 없다.
17. 숨김 리뷰는 미니앱 상품 평균별점·리뷰수와 리뷰 목록에서 제외된다.
18. 상품 등록·수정 에디터에서 이미지와 링크를 포함한 상세정보를 저장하고 재진입하면 동일하게 복원된다.
19. 위험 HTML·스크립트·이벤트 속성·허용되지 않은 URL은 저장 또는 출력 단계에서 제거된다.
20. DEV 프리뷰에서 레이아웃 템플릿, 컬러셋, 라이트·다크 테마를 각각 변경할 수 있다.
21. 메인 롤링 배너가 자동 전환되고 페이지 인디케이터로 직접 이동할 수 있다.
22. 초보 고객이 메인에서 라우터의 용도, 구매 이후 절차, 상품 선택 기준을 확인할 수 있다.
23. 개발 착수 전 3개 후보 중 공통 레이아웃 하나를 확정하며 운영 관리자에는 레이아웃 선택 기능이 노출되지 않는다.
24. 모든 후보와 최종 레이아웃의 상품 카드·상세·전체 리뷰 화면에서 평점과 리뷰를 확인할 수 있다.
25. 판매점·영업점은 스마트 에디터로 콘텐츠 페이지를 초안·공개·숨김 상태로 관리하고 공개 페이지를 배너 클릭 대상으로 연결할 수 있다.
26. 활성 배너에 연결된 콘텐츠 페이지 삭제가 차단되고 연결 해제 또는 숨김 안내가 표시된다.
